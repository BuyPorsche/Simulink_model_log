# Simulink Model Change Log（model_log）

**版本：V1.1** ｜ [English](readme_en.md)

在 MATLAB 会话中开启一次后，之后**任意 Simulink 模型保存**都会自动把结构与参数变更追加到模型同目录的 Markdown 变更日志中——覆盖模块增删、连线变化、参数新旧值对比，以及 Stateflow 状态机内部增删改。

与常见的「向模型注入 PreSaveFcn/PostSaveFcn 回调」方案不同，本工具通过**外部事件监听器（`Simulink.listener`）**实现零侵入：不修改模型文件本身，不在 `.slx` 里留下任何配置痕迹。

## 功能特性

- **会话级一键开关**：`start_model_log` 之后，当前 MATLAB 会话内所有模型（含之后新打开的）自动纳入记录，无需逐模型指定
- **保存即记录**：模块新增/删除/类型变更、参数新旧值、连线增删
- **参数采集面广且可配置**：默认采集全部 `DialogParameters` + Mask（封装）参数，外加 `config/param_whitelist.json` 配置项
- **布局噪声过滤**：`Position`、字体、颜色等纯外观变化不产生日志
- **Stateflow 状态机记录**（可选，需安装 Stateflow）：Chart 增删；状态、转移、数据的增删改
- **零侵入**：不改模型回调、不写 `.slx`
- **容错设计**：日志逻辑全程 try/catch，记录失败仅告警，**绝不阻塞保存**
- **整模型重同步保护**：路径变化等导致「全部模块被判为新增」时，识别为基线重同步而非真实变更，避免把整模型模块清单刷进日志
- **按模型独立版本计数**：日志节头显示 `Version: N`
- 纯 MATLAB 实现，无 MEX、无编译，跨平台

## 环境要求

| 依赖 | 要求 | 说明 |

| Simulink | 必需 | 核心功能面向 Simulink 模型 |

## 快速开始

```matlab
cd('D:\98_Github\Model_change_log')   % 换成你的本地仓库路径

start_model_log      % 开启（对当前会话所有模型生效，含新打开的模型）
```

之后正常工作：打开任意 `.slx`、编辑、**Ctrl+S** 保存即可。每个模型：

- 首次纳入记录时，先以「打开时刻的状态」建立基线快照（不计差异、版本为 0）；
- 之后每次包含实质变更的保存，追加一节日志，版本号 +1。

关闭：

```matlab
stop_model_log       % 停止本会话记录，已生成的日志文件保留
```

### 公开 API

| 入口 | 作用 |
|------|------|
| `start_model_log` / `stop_model_log` | 脚本形式一键开/关 |
| `model_log.enable()` / `model_log.disable()` | 等价函数式开/关 |
| `model_log.isEnabled()` | 查询当前是否启用 |
| `model_log.statePaths(modelPath)` | 求某个模型的日志/状态文件路径 |
| `model_log.toolVersion()` | 读取 `VERSION` 文件中的版本号 |
| `model_log.onMatlabStartup()` | `startup.m` 专用入口：启用并打印版本号 |
| `model_log.printBanner(status)` | 在命令行打印版本/状态横幅 |

## 生成的伴生文件

保存后，`.slx` 旁生成两个文件：

```text
MyModel.slx
MyModel_model_log.md        # 人类可读变更日志（追加式；建议提交进 Git 供评审）
.MyModel_model_log_.mat     # 内部状态快照（建议 gitignore，仓库默认已忽略）
```

日志格式示例（日志正文为英文，便于跨团队与 GitHub 阅读；本文档为中/英文说明）：

```markdown
# Simulink Model Log: MyModel

Auto-generated by model_log. Each save with changes appends a section.

##############################################################
## 2026-08-01 14:23:45 | Version: 3 | User: ELLX1JB | Model: MyModel
##############################################################

### Blocks Added
- `Controller/PID1` (BlockType: SubSystem)

### Parameter Changes
- Block: `Controller/Gain1`
  - Param: `Gain`
  - Old: `1`
  - New: `2.5`

### Line Changes
- Added: `In1/1` → `G1/1`
- Removed: `G1/1` → `Out1/1`

### Stateflow Changes
- State Changed: `Plant/Chart` / `On`
  - Field: `label/condition`
  - Old: `On\nentry: y=1;`
  - New: `On\nentry: y=2;`

---
```

## 工作原理

总体方案：**快照 + 差异对比（snapshot-diff）**——每次保存时完整采集模型结构与参数，与上一次的快照对比；不解析 `.slx` 压缩包、不依赖 visdiff。

```text
start_model_log / model_log.enable()
   ├─ 1. 在 groot appdata 上设置会话级启用标志
   ├─ 2. 在 Simulink 根对象（slroot）上监听 ObjectChildAdded
   │       —— 会话中出现任何新模型（新建/打开）时触发
   └─ 3. 给当前已加载的每个非库模型挂 3 个外部监听器：
           PostSaveEvent / PostLoadEvent / ObjectBeingDestroyed

新模型打开（ObjectChildAdded 触发）
   └─ 经 0.2 秒一次性 timer 延迟绑定（避免在事件回调内部注册的
      监听器不生效的问题）→ attachToModel

用户保存模型（PostSaveEvent 触发）
   ├─ 前置校验：已启用？非 library？模型已存盘（有 FileName）？
   ├─ 从 .mat 读取上一次的状态快照与版本号
   ├─ captureSnapshot() 采集当前完整快照
   ├─ diffSnapshots() 新旧对比，得到类型化变更记录
   ├─ 整模型重同步保护（见下文），必要时剔除海量结构噪声
   ├─ 差异非空 → formatLogSection() 渲染 → 追加写入 _model_log.md
   │      本次版本 = 上次版本 + 1
   ├─ 差异为空 → 不写日志（纯布局保存静默无痕）
   └─ 无论是否记录，都把新快照写回 .mat
   （以上全程 try/catch，任何异常仅 warning，不阻塞保存）

模型关闭（ObjectBeingDestroyed 触发）
   └─ 清理注册表中该模型的失效监听记录
```

### 快照采集内容

| 类别 | 采集字段 |
|------|----------|
| 模块身份 | 完整路径、`BlockType`、`MaskType`、`Name` |
| 参数 | 全部 `DialogParameters` + Mask 参数名 + 白名单配置附加项，值统一归一化为字符串 |
| 连线 | 「源模块/端口 → 目标模块/端口」对（自动去重） |
| Stateflow | Chart 清单；状态（名称/标签/分解方式）、转移（标签/源/目标）、数据（名称/作用域/数据类型） |

遍历方式：`find_system(..., 'LookUnderMasks','all', 'FollowLinks','off')` 遍历全部模块（注释除外）；连线通过各模块 `LineHandles` 的输出端口获取；Stateflow 通过 `sfroot` API 获取，按 SSID 稳定索引。

### 差异记录类型

| 类别 | 记录 |
|------|------|
| 模块 | 新增、删除、类型变更 |
| 参数 | 按参数名的新旧值对比 |
| 连线 | 新增、删除 |
| Stateflow | Chart 增删；状态/转移/数据的增删与字段级变更（标签、源目标、作用域、类型等） |

### 基线与版本号

- 打开一个**尚无**伴生 `_model_log.md` 的模型时，先保存「打开时刻」的快照作基线（`Version: 0`），不记录差异——避免首份日志被「全部模块新增」刷屏；已有日志的模型打开时不刷新基线。
- 之后每次**实际写入日志**的保存版本 +1，显示在节头 `Version: N`；每个模型独立计数。
- 状态 `.mat` 缺失或损坏（如换目录、误删）时，下一次保存自动重建基线，历史日志不受影响。

### 噪声过滤与重同步保护

- 内置忽略清单过滤 `Position`、`FontName`、`FontSize`、`FontWeight`、`FontAngle`、`ForegroundColor`、`BackgroundColor`、`NamePlacement`、`DropShadow`、`AttributesFormatString`、`Selected`、`Priority`、`Tag`、`UserData` 等布局/UI 字段；可在 `config/param_whitelist.json` 的 `ignore` 中追加。
- **重同步保护**：当基线丢失或模块路径整体改变，导致 diff 判定「当前模块全部为新增」（新增数 ≥ 当前模块总数）时，视为整模型重同步：丢弃批量结构增删记录，仅保留参数、连线、Chart 内部等真实编辑。首份日志场景下若无剩余差异，则直接重建基线（`Version: 0`）。

### 状态持久化

快照中的 `containers.Map` 不能直接写入 MAT，故保存前经 `packSnapshot`/`packChartMap` 展平为 `blockPaths`/`blockValues`、`chartPaths`/`chartValues` 等纯 cell 结构，读取时由 `unpackSnapshot`/`unpackChartMap` 重建，对上层逻辑完全透明。

## 参数记录配置

`config/param_whitelist.json`：

```json
{
  "common": ["SampleTime", "OutDataTypeStr"],
  "ignore": ["Position", "FontName", "FontSize", "FontWeight", "FontAngle",
             "ForegroundColor", "BackgroundColor", "NamePlacement",
             "DropShadow", "AttributesFormatString", "Selected"],
  "byBlockType": {
    "Gain":        ["Gain"],
    "Constant":    ["Value"],
    "Inport":      ["Port", "OutDataTypeStr", "Unit"],
    "Outport":     ["Port", "OutDataTypeStr", "Unit"],
    "SubSystem":   ["TreatAsAtomicUnit"],
    "Integrator":  ["InitialCondition", "GainValue"],
    "TransferFcn": ["Numerator", "Denominator"]
  }
}
```

| 字段 | 作用 |
|------|------|
| `common` | 对所有模块额外采集的参数名 |
| `byBlockType` | 按 `BlockType` 额外采集的参数名（叠加在 DialogParameters 之上） |
| `ignore` | 忽略的参数名（与内置清单合并） |

采集规则：`DialogParameters ∪ Mask 参数 ∪ common ∪ byBlockType`，再减去忽略清单。因此未列入白名单的模块同样记录参数变更；白名单的作用是「补充与排除」。

## 开机自启动（可选）

在 `userpath` 下的 `startup.m`（如 `C:\Users\<你>\Documents\MATLAB\startup.m`）末尾加入：

```matlab
% --- Simulink model_log ---
try
    addpath('D:\98_Github\Model_change_log');   % 改成你的仓库路径
    setupPath;
    model_log.onMatlabStartup();
catch ME
    warning('model_log startup failed: %s', ME.message);
end
```

启动时输出：

```text
[startup.m] model_log V1.1 loaded and ENABLED.
```

版本号集中写在仓库根目录的 `VERSION` 文件（当前 V1.1），升级只改该文件，`startup.m` 无需变动。

## 注意事项

| 事项 | 行为 |
|------|------|
| 持久性 | 启用状态仅当前 MATLAB 会话有效，重启后需重新执行（可经 `startup.m` 自启动） |
| 侵入性 | 不修改模型的 PreSaveFcn/PostSaveFcn，不写入 `.slx` |
| 作用范围 | 会话内所有模型；库（library）自动忽略；尚未保存过磁盘的模型（无 FileName）跳过 |
| 保存安全 | 日志任何失败仅 `warning`，绝不中断 `save_system` |
| 团队协作 | 建议把 `_model_log.md` 提交进 Git 作为变更评审依据；`.*_model_log_.mat` 保持 gitignore |
| 已知边界 | 不对比模型配置集（求解器等）、不递归模型引用、不对比数据字典；Stateflow 记录依赖 Stateflow 安装 |
