# Simulink Model Change Log (model_log)

**Version: V1.1** | [中文文档](README.md)

Enable it once in a MATLAB session, and every subsequent **Simulink model save** automatically appends structure and parameter changes to a Markdown change log beside the model — block additions/removals, wiring changes, old/new parameter values, and Stateflow chart internals.

Unlike the common approach of injecting `PreSaveFcn`/`PostSaveFcn` callbacks into the model, this tool works through **external event listeners (`Simulink.listener`)** and is fully non-intrusive: it never modifies the model file and leaves no trace inside the `.slx`.

## Features

- **One session-wide switch**: after `start_model_log`, every model in the current MATLAB session (including ones opened later) is covered automatically — no per-model setup
- **Log on every save**: block added/removed/type-changed, parameter old/new values, line added/removed
- **Broad, configurable parameter capture**: all `DialogParameters` + Mask parameters by default, plus entries from `config/param_whitelist.json`
- **Layout noise filtered**: pure cosmetic changes (`Position`, fonts, colors, …) produce no log entry
- **Stateflow chart logging** (optional, requires Stateflow): chart add/remove; states, transitions, and data — added/removed/changed
- **Non-intrusive**: no model callbacks touched, nothing written into the `.slx`
- **Fault-tolerant**: all logging logic runs in try/catch; failures warn but **never block the save**
- **Full-model resync guard**: when a lost baseline or wholesale path change makes "every block look newly added", it is treated as a baseline resync rather than a real change, so the log is not flooded with the entire block list
- **Per-model version counter**: each log section header shows `Version: N`
- Pure MATLAB implementation — no MEX, no compilation, cross-platform

## Requirements

| Dependency | Requirement | Notes |
|------------|-------------|-------|
| MATLAB | R2021b or newer recommended | Uses string API, `isfile`/`isfolder`, and the `Simulink.listener` event mechanism |
| Simulink | Required | Core functionality targets Simulink models |
| Stateflow | Optional | Chart internals are only logged when Stateflow is installed; skipped otherwise |
| Other toolboxes | None | No compiled artifacts, no external dependencies |

## Quick Start

```matlab
cd('D:\98_Github\Model_change_log')   % your local repo path

start_model_log      % enable for the whole session (models opened later included)
```

Then just work as usual: open any `.slx`, edit, **Ctrl+S**. For each model:

- On first capture, a baseline snapshot of the "as-opened" state is stored (no diff recorded, version 0);
- Every subsequent save containing real changes appends one log section and increments the version.

To stop:

```matlab
stop_model_log       % stop logging for this session; existing log files are kept
```

### Public API

| Entry point | Purpose |
|-------------|---------|
| `start_model_log` / `stop_model_log` | Script-style one-line enable/disable |
| `model_log.enable()` / `model_log.disable()` | Equivalent function calls |
| `model_log.isEnabled()` | Query whether logging is enabled |

| `model_log.printBanner(status)` | Print a version/status banner to the command window |

## Generated Sidecar Files

After a save, two files appear next to the `.slx`:


## How It Works

Overall approach: **snapshot + diff** — on every save, the full model structure and parameters are captured and compared against the previous snapshot. No `.slx` archive parsing, no visdiff dependency.

```text
start_model_log / model_log.enable()
   ├─ 1. Set a session-wide enable flag in groot appdata
   ├─ 2. Listen for ObjectChildAdded on the Simulink root object (slroot)
   │       — fires whenever a new model (created or opened) appears in the session
   └─ 3. Attach 3 external listeners to each currently loaded non-library model:
           PostSaveEvent / PostLoadEvent / ObjectBeingDestroyed

New model opened (ObjectChildAdded fires)
   └─ Deferred attach via a 0.2 s single-shot timer (listeners registered
      inside the ObjectChildAdded callback itself do not fire)

User saves a model (PostSaveEvent fires)
   ├─ Guards: enabled? not a library? model has a file on disk?
   ├─ Load previous snapshot + version counter from the .mat state
   ├─ captureSnapshot() — capture the current full snapshot
   ├─ diffSnapshots() — compare old vs new into typed change records
   ├─ Full-model resync guard (see below): strip mass-structure noise if needed
   ├─ Non-empty diff → formatLogSection() → append to _model_log.md
   │      version = previous version + 1
   ├─ Empty diff → write nothing (layout-only saves stay silent)
   └─ Either way, store the new snapshot back into the .mat
   (everything in try/catch — any error only warns, never blocks the save)

Model closed (ObjectBeingDestroyed fires)
   └─ Drop the stale listener registry entry for that model
```

### Snapshot Contents

| Category | Captured fields |
|----------|-----------------|
| Block identity | Full path, `BlockType`, `MaskType`, `Name` |
| Parameters | All `DialogParameters` + mask parameter names + whitelist extras; values normalized to strings |
| Lines | "source block/port → destination block/port" pairs (deduplicated) |
| Stateflow | Chart list; states (name/label/decomposition), transitions (label/source/destination), data (name/scope/data type) |

Traversal: `find_system(..., 'LookUnderMasks','all', 'FollowLinks','off')` walks all blocks (annotations excluded); lines are collected through each block's `LineHandles` output ports; Stateflow objects come from the `sfroot` API, indexed stably by SSID.

### Change Record Types

| Category | Records |
|----------|---------|
| Blocks | added, removed, type changed |
| Parameters | old/new value per parameter name |
| Lines | added, removed |
| Stateflow | chart add/remove; state/transition/data add/remove and field-level changes (label, source/destination, scope, type, …) |

### Baseline & Versioning

- Opening a model that has **no** sidecar `_model_log.md` yet stores an "as-opened" baseline snapshot (version 0) with no diff logged — this keeps the first log from being flooded with "all blocks added". Models that already have a log keep their baseline untouched on open.
- Every save that actually **writes a log section** increments the version, shown as `Version: N` in the section header. Counters are per-model.
- If the state `.mat` is missing or corrupt (moved folder, accidental delete), the next save rebuilds the baseline automatically; existing log history is unaffected.

### Noise Filtering & Resync Guard

- A built-in ignore list filters layout/UI fields such as `Position`, `FontName`, `FontSize`, `FontWeight`, `FontAngle`, `ForegroundColor`, `BackgroundColor`, `NamePlacement`, `DropShadow`, `AttributesFormatString`, `Selected`, `Priority`, `Tag`, `UserData`. Extend it via the `ignore` list in `config/param_whitelist.json`.
- **Resync guard**: when a lost baseline or wholesale block-path change makes the diff report "all current blocks as newly added" (added count ≥ total block count), it is treated as a full-model resync: mass structural add/remove records are dropped and only real edits (parameters, lines, chart internals) are kept. On a first log with nothing left, the baseline is simply rebuilt (version 0).

### State Persistence

`containers.Map` objects cannot be saved to MAT directly, so snapshots are flattened by `packSnapshot`/`packChartMap` into plain cell arrays (`blockPaths`/`blockValues`, `chartPaths`/`chartValues`, …) before saving, and rebuilt by `unpackSnapshot`/`unpackChartMap` on load. This is fully transparent to the rest of the code.

## Parameter Whitelist Configuration

`config/param_whitelist.json`:

```json
{
  "common": ["SampleTime", "OutDataTypeStr"],
  "ignore": ["Position", "FontName", "FontSize", "FontWeight", "FontAngle",
             "ForegroundColor", "BackgroundColor", "NamePlacement",
             "DropShadow", "AttributesFormatString", "Selected"],
  "byBlockType": {
    "Gain":        ["Gain"],
    "Constant":    ["Value"],
    "Inport":      ["Port", "OutDataTypeStr", "Unit"],
    "Outport":     ["Port", "OutDataTypeStr", "Unit"],
    "SubSystem":   ["TreatAsAtomicUnit"],
    "Integrator":  ["InitialCondition", "GainValue"],
    "TransferFcn": ["Numerator", "Denominator"]
  }
}
```

| Field | Purpose |
|-------|---------|
| `common` | Extra parameter names captured for every block |
| `byBlockType` | Extra parameter names captured per `BlockType` (on top of DialogParameters) |
| `ignore` | Parameter names to skip (merged with the built-in list) |

Capture rule: `DialogParameters ∪ mask params ∪ common ∪ byBlockType`, minus the ignore list. Block types not listed in the whitelist still get their parameter changes logged — the whitelist is for *additions and exclusions*, not restrictions.

## Auto-start on MATLAB Launch (Optional)

Append this to the `startup.m` in your `userpath` (e.g. `C:\Users\<you>\Documents\MATLAB\startup.m`):

```matlab
% --- Simulink model_log ---
try
    addpath('D:\98_Github\Model_change_log');   % your repo path
    setupPath;
    model_log.onMatlabStartup();
catch ME
    warning('model_log startup failed: %s', ME.message);
end
```

Startup output:

```text
[startup.m] model_log V1.1 loaded and ENABLED.
```

The version lives in the repo-root `VERSION` file (currently V1.1); upgrading means editing only that file — `startup.m` never changes.

## Notes & Limitations

| Item | Behavior |
|------|----------|
| Persistence | Enabled state lasts for the current MATLAB session only; re-run after restart (or use the `startup.m` auto-start) |
| Intrusiveness | Does not modify model PreSaveFcn/PostSaveFcn; nothing is written into the `.slx` |
| Scope | All models in the session; libraries are skipped automatically; models never saved to disk (no FileName) are skipped |
| Save safety | Any logging failure only issues a `warning`; `save_system` is never aborted |
| Team collaboration | Commit `_model_log.md` files to Git as review material; keep `.*_model_log_.mat` gitignored |
| Known limits | No configuration-set (solver, etc.) diffing, no recursion into model references, no data dictionary diffing; Stateflow logging requires Stateflow |
